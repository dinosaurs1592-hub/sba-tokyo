## 2. 状態管理

### 2.1 `PlayerState`

| 状態 | 入力受付 | 備考 |
|---|---|---|
| `Running` | プッシュ / 着地アクション(常時バッファ) | 地上走行 |
| `Airborne` | プッシュのみ即時。レーン/ジャンプ系は **バッファ** | **姿勢制御不可** |
| `Grinding` | プッシュ / ボードトリック / 離脱スワイプ | レール上滑走、速度減衰停止 |
| `GameOver` | リスタートのみ | ゲーム終了 |

> 旧仕様の `LandingWindow` は廃止し、**着地時に即座に評価する方式**に変更(下記 §4.2)。

### 2.2 レーン管理

- 論理レーン: `-1`(左) / `0`(中央) / `1`(右)
- レーン幅: `laneWidth = 3.0`(Inspector 調整可)
- 移動補間: `Mathf.SmoothDamp` で X 座標を補間。瞬間移動禁止。
- レーン移動完了時間: **0.18s**(`laneTransitionDuration`)
- レーン端での更なる外側スワイプは **無効**(レーン -1 で更に左スワイプ → 何も起きない)
- グラインド中の左右スワイプは **レール離脱 + レーン変更**(§4.3 参照)

## 3. 物理方針

**Kinematic Rigidbody + 手動 Transform 制御 + Trigger Collider**

| 要素 | 方式 | 理由 |
|---|---|---|
| 前進 | `transform.position.z` 加算 | フレーム独立・決定論的 |
| レーン移動 | `SmoothDamp` で X 補間 | 完了時間保証 |
| ジャンプ | `v0 + g·t` のスクリプト計算 | 物理エンジン非依存 |
| 衝突検出 | Kinematic Rigidbody + Trigger Collider | 押し戻し干渉なし、`OnTriggerEnter` で確実検出 |
| グラインド | レール曲線/直線に座標吸着 | レール座標系で計算 |
| 重力定数 | 自前 `gravity = -25.0`(Inspector) | Physics 設定と独立 |

**理由:** ランナーゲームは物理シミュレーションより動作再生に近い。決定論性が SS ジャンプのような微妙ジェスチャーゲーと相性良い。

## 4. 入力仕様

### 4.1 状態非依存アクション(常時受付)

| アクション | 入力 | 処理 |
|---|---|---|
| **プッシュ(加速)** | 下フリック / S | `CurrentSpeed += pushAmount`、`lastPushTime` 更新 |

`idleDecayDelay` 経過後、`speedDecayPerSecond` で毎フレーム減衰。  
`Grinding` 中は減衰停止。

### 4.2 着地時アクション(**先行入力バッファ方式・2 値判定**)

> **コアコンセプト:** 空中で入力されたアクションは **バッファされ、着地の瞬間に評価される。** ウィンドウ概念および着地後の入力受付は完全に廃止。**「着地時に正しい入力がバッファされていたか」のみで Perfect / Miss を二値判定する。**

| アクション | 入力 | 処理 |
|---|---|---|
| **スライド** | 左右スワイプ | `targetLane ±= 1` |
| **スライドジャンプ** | 斜め上スワイプ(角度 30°〜60°) | `targetLane ±= 1` + `v0 = jumpForce` |
| **スーパースライドジャンプ(SS)** | L字 / V字ジェスチャー | `targetLane ±= 2` + `v0 = jumpForce * 1.4` |
| **タップ** | 画面タップ | 面別に意味が変わる(§5.2 参照) |
| **ジャンプ(単発)** | 上スワイプ | `v0 = jumpForce` |

**バッファ仕様:**
- バッファ容量: 直近 1 入力(古いものは上書き)
- バッファ生存時間: **0.5s**(空中で入力 → 0.5s 以内に着地しないと失効)
- 着地時評価: **バッファ存在のみで判定**(タイミング差は使わない)
- **着地後の入力は評価対象外**(着地後にスワイプ/ジャンプを入力しても Perfect にならない、次の空中遷移までバッファされない)
- バッファ済 = **自動的に Perfect 扱い**(§5.1)

### 4.3 レール

| アクション | 入力 | 処理 |
|---|---|---|
| **グラインド突入** | レール接触で自動 | `state = Grinding`、速度減衰停止 |
| **ボードトリック** | Grinding 中に下スワイプ | アニメ + コンボ +1 + Score +150 |
| **レール離脱(自動)** | レール終端到達 | 自動的に `Airborne` へ遷移、ジャンプはなし |
| **レール離脱(手動)** | Grinding 中に左右スワイプ | レーン変更 + `Airborne` 遷移 |

### 4.4 衝突

| 対象 | 処理 |
|---|---|
| 障害物(`Tag: Obstacle`) | **即時 `CurrentSpeed = 0` → ゲームオーバー** |
| 穴(着地予定地に床なし) | **即時ゲームオーバー** |

> カウンタートリックは **採用しない**(廃止確定)。回避はジャンプ/レーン移動のみ。

## 5. 着地評価ロジック

### 5.1 評価ロジック(2 値判定)

| バッファ状態 | ラベル | 処理 |
|---|---|---|
| バッファ存在 + 面が要求するアクション一致(§5.2) | **Perfect** | コンボ +1, Score +200, Speed +`speedBonus` |
| 上記以外(バッファなし or 面とアクション不一致) | Miss | Perfect 報酬なし。コンボは §5.3 に従う |

> **旧 Good 階層は廃止。** 「先行入力できたか」のみで判定する完全二値設計。  
> Miss = ゲームオーバーではない。「Perfect 報酬がもらえないだけ」で、衝突や穴落ちと混同しないこと。

**チューニング値:**
- `speedBonus = 4.0`(Perfect 時のみ加算)

### 5.2 面別着地ルール

着地面の `SurfaceType` と バッファ入力の組み合わせで Perfect 成立を判定する。

| 面 | Perfect 成立アクション | 不一致時(コンボリセットなし) |
|---|---|---|
| `Ground` | Tap / Swipe / Jump / SlideJump / SS のいずれか | バッファなし → Miss(コンボ維持) |
| `Object` | **Jump / Swipe / SlideJump / SS のみ**(Tap は Perfect にならない) | Tap バッファ = 無効入力(コンボ維持、報酬なし) |
| `Rail` | Tap / Swipe / Jump / SlideJump / SS / RailTrick | バッファなし → Miss(コンボ維持) |

> **Object 面の代表例:** 走行中の **車**(車のボンネット・屋根に飛び乗る)。  
> JSR 風の「キメ」着地。タップでは決まらず、跳び込み系(Jump/Swipe)のみ評価される。  
> Tap で着地しても **コンボはリセットされない**(寛容設計)。Perfect 報酬を逃すだけ。

### 5.3 コンボリセット条件

| 条件 | 結果 |
|---|---|
| 着地時にバッファ入力なし → そのまま着地 | コンボ維持(走行継続) |
| Object 面で Tap バッファ → 不一致着地 | コンボ維持(報酬なし、ペナルティなし) |
| **入力なし状態が 3.0s 継続** | **コンボリセット**(`comboTimeoutSeconds = 3.0`) |
| 障害物衝突 / 穴落ち | ゲームオーバー(コンボ無関係) |

> 「入力」の定義: **Push、または Perfect 着地**。  
> 平坦区間で Push のみで走り続ければコンボは維持される(息継ぎ可能)。

## 6. オートドライブモード(フェーズ4 仮設定)

### 6.1 突入条件
- `ComboCount >= 20`(`autoDriveThreshold`)
- 突入時:`CurrentSpeed = MaxSpeed` に固定、無敵化、`autoDriveDuration = 8.0s` カウント開始

### 6.2 中の挙動
- 障害物衝突無効、穴も自動回避
- 自動でレーン移動 + 最適アクション(視覚演出)
- **スコア倍率 2.0x 固定**(`autoDriveScoreMultiplier = 2.0`、増減なし)
- **タップ入力でコンボ +1**(視覚的に JSR 風グラフィティが画面に展開)
  - クールダウンなし、連打可能(ただし 1 タップ = 1 コンボ加算)
  - コンボ加算 SFX も発火

### 6.3 終了
- `autoDriveDuration` 経過 → 通常状態へ復帰
- **コンボは継続**(値を維持して通常モードへ)
- スコア倍率は 1.0x にリセット

## 7. レベルデザイン(チャンク生成)

### 7.1 チャンクシステム
- 3レーン規格に適合した `Chunk` プレハブの組み合わせ
- **オブジェクトプーリング必須**(カメラ後方は破棄せず再利用)
- 各チャンクは `entry` / `exit` の Z 座標を自己申告(`ChunkController`)

### 7.2 チャンク種別(最低 5 種)

| プレハブ | 内容 |
|---|---|
| `ChunkFlat` | 平坦、障害物なし(息継ぎ) |
| `ChunkObstacleRun` | 3レーンに障害物パターン |
| `ChunkRailSection` | レール区間(グラインド可能) |
| `ChunkObjectPlatform` | 段差オブジェクト面(ジャンプして Tap 着地) |
| `ChunkMixed` | レール + 障害物の組み合わせ |
| `ChunkGap` | **穴あり**(ジャンプ強制) |

### 7.3 難易度スケーリング

| 距離 | 障害物密度 | 速度減衰 | 最高速 |
|---|---|---|---|
| 0〜200 m | 基準 | 基準 | 52 |
| 200〜500 m | +20% | +0.5/s | 52 |
| 500 m〜 | +40% | +1.0/s | 64 |
| 1000 m〜 | +60% | +1.5/s | 72 |

`ChunkGap` の出現率は 200m 以降に解放。

## 8. ゲームオーバーとリセット

| 条件 | トリガー |
|---|---|
| `CurrentSpeed <= 0` | プッシュ怠慢、衝突、穴落ち |
| 障害物衝突 | 即時 |
| 穴落ち | 即時 |

リセット:`SBAGameManager.ResetRun()` → `RunReset` イベント発火、全システム初期化。

リバイブ仕様は [`game_design.md`](game_design.md) §3 を参照。

## 10. 前方互換契約(変更・削除禁止)

- `PlayerState` 既存値:`Running`, `Airborne`, `Grinding`, `GameOver`
  - `LandingWindow` は **本改訂で削除確定**(先行入力バッファ方式へ完全移行)
- `SurfaceType` 既存値:`Ground`, `Object`, `Rail`, `Obstacle`(変更禁止、`Object` の意味は §5.2 参照)
- `LandingActionType` 既存値:`None`, `Tap`, `Swipe`, `Jump`, `RailTrick`
  - 追加予定:`SlideJump`, `SuperSlideJump`(M7 / M20)
- `RegisterLandingResult(actionType, elapsedSinceLanding)` の `elapsedSinceLanding` 引数は **廃止予定**(常に 0 で渡す、フェーズ4 で削除)

## 11. SS ジャンプ判定基準(フェーズ4 仮設定)

スワイプ軌跡に **角度変化点(直角折れ)** を検出し、L 字 / V 字を判別する。

| ジェスチャー | 検出基準 |
|---|---|
| **L字** | 1 箇所で角度差 75° 超(直角折れ) |
| **V字** | 角度差 75° 超の折れ + 折れ前後の方向が逆向き(内積負) |
| 失敗 | 上記いずれにも該当せず → **通常スライドジャンプにフォールバック**(角度 30°〜60° なら) |

> サンプリング間隔・閾値の微調整・スワイプ最小長などの実装詳細は実装時にコードコメントで管理する(M20 着手時に決定)。

## 12. MVP(フェーズ2)成功基準

- [ ] 空中入力が **着地時に評価される**(リズムゲー化)
- [ ] スライドジャンプが斜め上スワイプで発火する
- [ ] チャンク生成で意図あるパターンを感じる
- [ ] 穴落ちで即死する
- [ ] コンボが 10 回以上継続できる体感
- [ ] 3.0s 無入力でコンボがリセットされる
- [ ] バッファ生存時間 0.5s が **モバイル実機で取れる**(空中入力 → 着地まで間に合う)
- [ ] Object 面(車)に Jump で乗ってコンボがつながる

## 13. 廃止項目

| 項目 | 理由 |
|---|---|
| カウンタートリック | 衝突=即死のシンプル設計に統一 |
| `LandingWindow` ステート | 先行入力バッファ方式に移行 |
| **Good ティア** | バッファ済 = 即 Perfect の 2 値設計に簡素化 |
| **着地後の入力受付** | 完全に「先行入力のみ」化、予測勝負ゲー |
| **`landingWindowDuration` パラメータ** | 着地後評価が消えたため不要 |
| **`perfectLandingWindow` パラメータ** | 同上(2 値判定に簡素化) |
| **オートドライブ中タップで scoreMultiplier 増加** | 倍率 2.0x 固定 + タップでコンボ +1 に置換 |
| **Object 面 Tap 必須ルール** | Tap 不要、Jump/Swipe で Perfect の方向に反転 |
